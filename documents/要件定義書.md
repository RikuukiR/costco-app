# COSTCO 業務効率化システム 要件定義書

## - 売上予測機能を核とした統合管理システム -

---

## 1. プロジェクト概要

### 1.1. 課題

COSTCO での業務は時間との闘いになることが多く、現場業務の中には**Web アプリを活用することによって省くことのできる無駄**が存在している。
COSTCO は他の同業種の小売店とは異なり、**スタッフの業務効率化及び最適化によって利益を創出**する企業モデルであるため、その無駄を解消することは利益向上に直結し、さらなる発展に繋がる。

### 1.2. 目的

自身が経験した Deli 部署における**業務の効率化及び最適化**を目的とし、他部署にも応用可能な部分は後から機能を追加できるよう配慮する。

---

## 2. システム概要

### 2.1. 主な機能

1.  **売上予測機能**

    - 日別/週別/年別での売上データ表示
    - Chart.js による視覚的なグラフ表示
    - 曜日別目標金額の設定・表示
    - OpenAI API を活用した売上傾向予測コメント

2.  **商品（SPEC）管理**

    - 商品の新規登録・編集・削除・一覧表示
    - spec_code（製造番号）による管理

3.  **売上管理**
    - 売上データの登録・蓄積機能
    - 売上予測機能との連携

### 2.2. システム構成

- **フロントエンド**: Laravel Blade テンプレートエンジン, JavaScript
- **バックエンド**: PHP (Laravel)
- **データベース**: MySQL
- **デプロイ環境**: VPS

### 2.3. 技術スタック

- **バックエンド**: PHP 8.x + Laravel 8.x
- **フロントエンド**: JavaScript + Chart.js
- **データベース**: MySQL 8.x
- **インフラ**: Docker + Docker Compose + Nginx
- **外部 API**: OpenAI GPT API（売上予測コメント生成）
- **認証**: Laravel Fortify

## 4. 現状分析と解決アプローチ

### 4.1. 現状の課題

1.  **時間のロス**

    - 在庫確認・外部発注数量の把握に時間がかかる
    - 急な売れ行き変化への対応で製造数調整が遅れる
    - 目視確認に依存した判断プロセス

2.  **経済的損失**

    - 作りすぎによる食品ロス
    - 廃棄費用の増加
    - 残業代の増加

3.  **管理の非効率性**
    - 紙面での管理による人的ミス
    - 管理職の経験頼みの予測
    - リアルタイムな情報共有の困難

### 4.2. 解決アプローチ

1.  **データドリブンな売上予測**

    - 過去売上データの蓄積・分析
    - 曜日別目標設定による計画的運営
    - AI 活用による客観的な傾向分析

2.  **リアルタイム可視化**
    - グラフによる直感的な理解
    - 日/週/年での多角的分析
    - モバイル対応による現場アクセス

## 5. 機能仕様

### 5.1. 機能一覧

#### A. 売上予測機能

- 日別/週別/年別売上グラフ表示
- 曜日別目標金額設定（月〜日: 180 万〜480 万円）
- Chart.js による視覚的表示
- OpenAI API 活用の予測コメント生成
- キャッシュ機能による高速表示

#### B. 商品（SPEC）管理

- 商品新規登録・編集・削除
- spec_code（5 桁製造番号）管理
- 商品名・価格・目標重量・カテゴリ管理

#### C. 売上管理

- 売上データ登録機能
- 売上予測機能との連携
- 過去データ蓄積システム

#### D. 食材管理

- 食材発注機能（管理職のみ）
- 使用食材登録機能（スタッフも可能）
- 在庫確認機能（スタッフも閲覧可能）

#### E. VOLUME 管理（外部発注管理）

- 発注概要登録・編集（管理職のみ）
- 発注概要閲覧（スタッフも可能）
- 発注元・商品名・数量・合計・日付管理

#### F. DESTROY 管理（廃棄管理）

- 廃棄量登録・閲覧機能
- 廃棄理由・日付・金額管理

#### G. WEIGHT 管理（品質管理）

- 商品重量実測値登録
- 目標重量との乖離チェック・アラート機能

#### H. 製造予定管理

- 製造予定（時間・工程）登録・閲覧（管理職のみ）
- 工程管理・進捗確認

## 7. 非機能要件

### 7.1. パフォーマンス

- ログイン後の主要画面は 3 秒以内に表示する。
- グラフ描画は 2 秒以内に完了する。
- API 応答時間は 1 秒以内とする（キャッシュ活用）。

### 7.2. 利用時間・負荷

- **対象時間**: 平日 5:00〜20:00（営業時間）
- **繁忙期対応**: 24 時間アクセス可能
- **同時アクセス**: 最大 50 ユーザーを想定

### 7.3. セキュリティ

- Laravel Fortify による認証機能を実装する。
- CSRF 対策を実装する。
- API キーは環境変数で管理する。

### 7.4. 拡張性

- 将来的な大量データに対応するため、ページング機能を実装する。
- 機能追加が容易なモジュール化された設計とする。

## 8. 利用シナリオ

### 8.1. 管理職の日常業務

1.  **朝の売上確認** (7:00-8:00)

    - 前日の売上実績を確認する。
    - 週間・月間トレンドをグラフで把握する。
    - AI による予測コメントを参考に、当日の傾向を分析する。

2.  **製造計画立案** (8:00-9:00)
    - 曜日別の売上目標と実績・予測を比較する。
    - 週末の売上予測を確認し、仕込み量を計画する。
    - データに基づき、各商品の製造数を調整する。

### 8.2. スタッフの日常業務

1.  **売上目標確認** (適時)
    - 当日のチーム目標金額を確認する。
    - 現在の売上進捗状況をリアルタイムで把握する。

## 9. 成功指標

### 9.1. 定量的指標

- **業務効率化**:
  - 売上確認・分析時間を 30 分から 5 分に短縮する (83%短縮)。
  - データ入力時間を紙媒体での管理と比較して 50%短縮する。
- **予測精度**:
  - 売上予測の的中率を 70%以上とする。
  - AI 予測コメントの有用性を 80%以上とする。

### 9.2. 定性的指標

- **ユーザー満足度**:
  - 「管理が楽になった」と感じるユーザーを 80%以上とする。
  - 「直感的で使いやすい」と感じるユーザーを 75%以上とする。
- **ミス軽減効果**:
  - 製造漏れや記入漏れを 50%減少させる。
  - データ入力ミスを 70%減少させる。

### 9.3. 経済効果（期待値）

- **利益向上**: 機能導入前と比較して 5%増加させる。
- **残業代削減**: 月間 20 時間削減する。
- **廃棄ロス削減**: 食品ロスを 15%削減する。

## 10. リスクと対策

### 10.1. 技術的リスク

- **OpenAI API 障害**: キャッシュ機能とフォールバック機能で対応する。
- **データベース負荷**: インデックス最適化とキャッシュで対応する。
- **モバイル対応**: レスポンシブデザインで対応する。

### 10.2. 運用リスク

- **ユーザー教育**: 段階的な導入とマニュアル整備で対応する。
- **データ移行**: 既存の紙媒体データを段階的にデジタル化する。
- **メンテナンス**: リモート対応可能な構成とする。
